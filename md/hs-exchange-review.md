# hs-exchange — Project Review

## Что это

Статичное веб-приложение для учёта обмена картами в игре.
Карты номинируются в звёздах (1★–5★), бывают **новыми** или **дублями**.
Данные также используются для внешнего анализа (экспорт JSON), поэтому в них хранятся готовые агрегаты.

## Архитектура данных

Хранилище: `localStorage`, ключ `cardTracker`.
**Ключ не меняется при смене версии формата** (иначе пользователь теряет данные). Формат мигрирует на лету, версия есть только в экспортируемом JSON (сейчас `version: 4`).
Язык хранится отдельно: ключ `hs-exchange-lang`.

```js
state = {
  isNewCard:    bool,    // переключатель "новая карта" на панели
  viewAll:      bool,    // режим "все сезоны"
  sortBy:       string,  // 'balance' | 'new_cards' — сортировка таблицы
  activePlayer: string,  // нормализованный ключ активного игрока
  lastAction:   object,  // { playerKey, group, starIndex, delta } — для отмены

  current: {
    name:            string,
    start_date:      ISO string,
    received_new:    [0,0,0,0,0],  // АГРЕГАТ по всем игрокам сезона
    received_double: [0,0,0,0,0],  // АГРЕГАТ
    sent:            [0,0,0,0,0],  // АГРЕГАТ
    players: {
      normKey: {
        name:            string,
        received_new:    [0,0,0,0,0],  // по звёздности 1★–5★
        received_double: [0,0,0,0,0],
        sent:            [0,0,0,0,0],
        note:            string,
      }
    }
  },

  history: [
    {
      name:       string,
      start_date: ISO string,
      end_date:   ISO string,
      received_new, received_double, sent,   // АГРЕГАТЫ, переезжают сюда вместе с сезоном
      players:    { normKey: { name, received_new, received_double, sent } }
    }
  ]
}
```

Ключ игрока (`normKey`) = `norm(name)` = `name.trim().toLowerCase()`.

### Агрегаты на уровне сезона

Сумма массивов по всем игрокам сезона. Нужны в первую очередь для внешнего анализа файла.

- **Миграция и целостность:** при загрузке и импорте `ensureSeasonTotals()` проверяет **наличие полей** (а не версию). Если полей нет, считает агрегат. Чтобы принудительно пересчитать после ручной правки истории, достаточно удалить поля у сезона.
- **Инкрементально:** `quickAdd` (+1) и `undoLast` (−delta, не ниже 0) правят и игрока, и `state.current`.
- **Полный пересчёт** через `recalcSeasonTotals(state.current)`: `saveEdit`, `deletePlayer`, `renamePlayerKey` (при слиянии игроков). Правка редкая, пересчёт проще, чем хранить дельту.
- **Новый сезон:** `newSeason` архивирует `current` вместе с агрегатами и создаёт новый `current` с нулевыми агрегатами.

## Ключевые функции JS

| Функция | Назначение |
|---|---|
| `mergeAllPlayers()` | Агрегация игроков `current` + всех сезонов `history` в один словарь |
| `sortedPlayers()` | Отсортированный массив `{key, p, bal, new_cards}` с учётом `viewAll` и `state.sortBy`; при равенстве — по имени asc |
| `setSortBy(key)` | Меняет `state.sortBy`, сохраняет, перерисовывает |
| `playerTotals(d)` | Считает всю статистику по одному объекту (игрок или агрегат) |
| `aggregatePlayers(dict)` | Суммирует словарь игроков в один объект |
| `recalcSeasonTotals(season)` | Пересчитывает агрегаты сезона из `players` |
| `ensureSeasonTotals()` | Досчитывает агрегаты у сезонов, где полей нет (старт и импорт) |
| `appendDataCells(tr, totals)` | Числовые ячейки строки (renderTable и renderTotalsRow) |
| `t(entry, vars)` | Перевод через объект из `strings`; плейсхолдеры `{name}` |
| `applyTranslations()` | Проход по `[data-i18n]`: `textContent`, `title`, `aria-label` (включая `<title>` страницы) |
| `updateSeasonWrap()` | Обновляет `season-input` (readonly + текст в режиме viewAll) |
| `setViewAll(val)` | Переключение режима текущий/все сезоны |
| `setLang(lang)` | Смена языка, сохранение в localStorage, перерендер |
| `showConfirm(msg, ok, cancel)` | Promise-based диалог подтверждения |

## i18n

Два объекта в `hs-exchange-i18n.js`:

- **`i18n`** — для DOM-перевода через `applyTranslations()`. Ключ = значение `data-i18n` или `id` элемента. Суффиксы:
  - `key.title` → атрибут `title`
  - `key.aria` → атрибут `aria-label`
- **`strings`** — для JS через `t(strings.key)`. Поддерживает плейсхолдеры.

Формат записи: **один язык — одна строка**, внутри записи:
```js
'key': {
  en: '...',
  ru: '...',
  de: '...',
},
```

Перевод заголовка вкладки: `<title data-i18n="app-title">`.

Язык по умолчанию: `localStorage` → `navigator.language` → `'en'`.

## Интерфейс

### Хедер
```
[ season-input ⟳ ]  [ 🌐 ]  [ ☰ ]
```
- `season-input` — одно поле: редактируемое (обычный режим) или readonly «All seasons» (viewAll). Ширина 150px по умолчанию, `max-width: 200px`, `field-sizing: content` (авто-подгонка там, где браузер поддерживает)
- `⟳` — переключатель режима current/all
- `🌐` — выбор языка (English / Deutsch / Русский)
- `☰` — меню: новый сезон, статистика сезонов, экспорт (файл / буфер), импорт (файл / буфер)
- Меню справа: `menu-dropdown` `right: 0`, `lang-dropdown` `right: 36px`. Открытие одного закрывает другое

### Таблица
- Числовые ячейки **read-only**
- **Сортировка по клику на заголовок:** «Balance ★» (`balance`) и «New» (`new_cards`, новые полученные карты, показывает «полезность» игрока для обмена). Активная колонка подсвечивается акцентом и стрелкой ↓. Остальные заголовки не кликабельны
- Кнопки в строке: **ℹ** (статистика), **✎** (редактирование), **✕** (удалить)
- В режиме `viewAll`: ✎/✕ скрыты, поле примечания disabled
- Последняя строка — итоги по всем игрокам

### Быстрая панель (фиксированная внизу, `--panel-h: 130px`)
- Переключатель «Новая карта» / «Дубль»
- Кнопки 1★–5★ для получено/отдано
- Кнопка «↩ Отмена» (откат последнего действия)
- Скрывается в режиме `viewAll`

### Модалы
| ID | Назначение |
|---|---|
| `modal-edit` | Точное редактирование данных игрока (3×5 grid) |
| `modal-stats` | Статистика по игроку или всем игрокам, с выбором сезона (список слева, детализация справа) |
| `modal-confirm` | Promise-based диалог подтверждения |
| `modal-paste` | Вставка JSON из буфера (fallback для clipboard API) |

### Прочее
- Favicon: inline SVG в `<link rel="icon">`, золотая звезда ★ на тёмном скруглённом фоне, `y='48'`

## Соглашения по коду

- `createElement(tag, classes, attrs, text)` + `appendElement(parent, ...)` вместо `innerHTML`
- `addHandler(id, type, fn)` для одиночных обработчиков
- Массив `handlers[]` в `DOMContentLoaded` для блочной инициализации
- `data-i18n` без значения → ключ = `id` элемента; с значением → явный ключ
- Модалы закрываются через `data-closes="modal-id"` на кнопке (один `querySelectorAll` в init)
- `pt` (не `t`) для результата `playerTotals()`, чтобы не конфликтовать с функцией перевода
- Отступы: 2 пробела

---

## Принятые решения

- **Ключ localStorage постоянный** (`cardTracker`). Не привязывать к версии формата: миграция на лету, а не сменой ключа.
- **Миграция по наличию полей**, а не по номеру версии: позволяет пересчитать агрегаты, если история правилась вручную.
- **Статистика и итоговая строка пока считаются по игрокам** (`aggregatePlayers`/`mergeAllPlayers`), а не из агрегатов сезона. Попытка перевести `getStatsData` и `renderTotalsRow` на готовые агрегаты была откачена: код стал длиннее (дополнительные ветки `viewAll` / `statsPlayerKey`), а выигрыша при таком объёме данных нет. Агрегаты пока служат внешнему анализу. Не повторять без нового, более простого подхода.
